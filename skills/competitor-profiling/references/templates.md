# Competitive evidence and output templates

The shared context-establishment contract owns the schema. These are domain
checks and a compatible minimum when that contract is not installed.
Use the relevant mode section, plus the specialist-return packet on every run.

## Evidence, confidence, and contradictions

Use Sourced / Assumed / Gap separately from kind, verification, availability,
confidence, approval, and health. Sourced means citable, not automatically true
or approved. Expose formulas and labeled inputs without a Derived evidence tag.

Use High / Medium / Low confidence with a rationale based on directness, method,
applicability, independence, bias, freshness, and counterevidence. A single original
release record can substantiate an announcement, not future availability or impact.
Multiple articles repeating it remain one source. No universal count establishes
sufficiency. Reuse never upgrades confidence or approval.

Unknown means not established. Explicitly absent requires scoped evidence such as
an applicable entitlement exclusion or authoritative limitation record.
Keep self-reported claims separate from documented or tested behavior.
Confidence in a verified event can be high while its commercial implication is low.

Record CTR ID, linked findings, scope/type, affected decisions, severity, owner,
proposed disposition/status, and resolution evidence or smallest test.
Types: scope, time/version, definition/measurement, reporter, evidence versus
interpretation, decision conflict, factual conflict, evidence against canon.
A scoped temporal explanation needs effective-date evidence. Newer wording alone
cannot settle an unresolved factual conflict. Hold consequential dependent claims
while continuing independent research. One material contradiction merits review
without repeated signals, even outside the current ICP.

## Specialist-return packet

Preserve project-scoped IDs and reuse sources instead of counting derived copies.
Attach this packet to the domain artifact rather than creating another store.

```yaml
contract: pmm-context-v1
artifact: research-return
project: [project]
product_scope: [scope]
id: [return ID]
version: [artifact version]
updated: [date]
owner: competitor-profiling
goal: [question/intended action]
return_to: [originating PMC workflow or requester]
```

Omit inapplicable fields. Unknown source metadata remains explicit.
Return status: answered | partially answered | inconclusive | unable to complete.

Source inventory: SRC ID; location/precise locator; material type; author/reporter
and role; event/collection date; source version; ingestion date; scope/coverage;
inspection state; original/derivative IDs; limitations/access/use restrictions.

Each reusable finding: FND ID; statement/kind (evidence, interpretation, assumption,
historical/current approved decision, unknown); evidence label; sources/locators;
supporting/opposing findings; scope; method/derivation; meaningful denominator;
confidence/rationale; approval reference when real or unapproved/unknown status;
limits; expiry/review trigger. Include verification/availability where applicable.

Return questions and GAP/HND IDs addressed; method/sample and limitations;
completion criteria met/unmet; unanswered questions; domain artifact link;
unapproved context implications and proposed destinations; consumer/owner handoffs.
A report alone does not close a gap. Preserve old findings and supersession links.

## Readiness and canonical handling

| Requirement | Why needed | Source/version | Support | Authority | Health | GAP ID | Evidence readiness | Permitted next action | Approval dependency |
|---|---|---|---|---|---|---|---|---|---|

Support: evidence, interpretation, assumption, unknown.
Authority: approved, proposed, unapproved, approval unknown.
Health: current, stale, conflicting, superseded, missing.

- PROCEED means evidence sufficiency for this action, never approval.
- PROCEED PROVISIONALLY records assumption, risk, permitted scope, validation trigger.
- HOLD THIS DECISION identifies consequential gap, owner, and completion criteria.
  Continue independent work. Missing approval is a separate dependency.

PMC integrates the return. Competitive findings can be proposed for
living/06-competitive.md, evidence for living/07-evidence.md; select one claim home
and reference elsewhere. SSOT owns destinations and canonical persistence.
Baseline: setup proposal → Gate 2. Existing canon: scan → Gate 1 → proposal → Gate 2.
Human approval remains required. Research verification grants no canon approval.

End with ranked gaps covering every Assumed/Gap item. Top five in body, remainder
in appendix. Include counterfactual impact, priority/type, existing finding IDs,
retrieval/test, primary owner/contributors, completion criteria, status,
dependencies, return_to, and resolution milestone. Mark suggested assignments.


## Return completeness check

Before delivering, check each finding for scope, source/locator, method, confidence
rationale, approval status, limits, and review trigger. Mark missing metadata
unknown; a generic artifact note does not supply missing field-level status.
Check each contradiction and gap against the required fields above. Show support,
authority, health, permitted action, and approval dependency for task-critical
readiness items. Report unmet completion criteria instead of claiming a complete
return because the domain report exists.
